# M0.5 — LoopBridge technical feasibility

**Status:** desk research and design proposal. Sources consulted on **2026-11-10**. There is no deployed Bridge, selected RPC framework or validated adapter. **High** confidence denotes a documented interface. **Medium** denotes expected integration with version, OS policy or application dependencies. A documented interface is evidence of an upstream contract, not of a working LoopEnvironment deployment.

The [Linux foundation study](M0_5_LINUX_FOUNDATION.md) covers the graphical stack, accessibility providers and VM graphics. The [recommendations](M0_5_RECOMMENDATIONS.md) define the proposed experiment sequence. The [LoopBridge contract](../LOOPBRIDGE.md), [security model](../SECURITY_MODEL.md) and [accepted ADRs](../DECISIONS/README.md) remain authoritative for product boundaries.

## Where the service runs

Run an unprivileged Bridge in the graphical session's security context. For M1, one dedicated desktop account, one graphical session and disposable fixture data make the ownership boundary observable. Bind each Bridge instance to an explicit session, seat and compositor/accessibility endpoints. A systemd user manager or user D-Bus may be shared across sessions of the same UID. UID, inherited environment and a user-service name are insufficient session identifiers. Verify the endpoint against the managed session, rebind only on explicit lifecycle changes and invalidate all handles on restart or logout. Close input and capture on lock or inactive session according to policy. For concurrent product sessions, define isolation before allowing multiple desktops under one UID. [logind D-Bus][S1], [XDG runtime directory][S2], [D-Bus broker configuration][S3].

Separate the public API/policy boundary from the adapter interfaces. The Bridge authenticates clients, narrows capabilities, filters state and dispatches vetted actions. Adapters reach Sway IPC, AT-SPI, desktop portals, a local media helper, logind or a constrained process/file interface. A client cannot submit raw IPC, D-Bus destinations/members, shell commands, file descriptors or adapter control strings. A narrow adapter API limits what the Bridge can ask for. A process that already has the underlying socket or bus permissions can still bypass the Bridge. The containment of untrusted local clients must therefore be an OS property, with a separate UID or a sandbox that cannot access the Wayland/X11 sockets, raw compositor IPC, accessibility bus, input devices or the session's credential store. Test this separation before treating the Bridge as the session's exclusive control boundary. [Sway IPC][S4], [Flatpak sandbox boundaries][S5], [D-Bus broker configuration][S3], [ADR 0005](../DECISIONS/0005-security-and-transport.md).

If a later use case needs system administration, add a narrowly scoped, independently reviewed helper for named operations. Prefer calling an existing system service with documented authorization when its interface matches the operation. A minimal, service-owned polkit action may mediate OS authorization, while Bridge client identity, session and grants still need independent enforcement. A system service sees the Bridge or helper as its D-Bus caller. It cannot infer which agent requested the operation, so a permissive rule for the Bridge can create a confused deputy. A helper must enforce its own resource scope, validate kernel-authenticated callers and derive authorization from trusted state. Missing polkit agent, challenge, timeout or denied action fails closed. No privileged helper is required for M1. [systemd manager D-Bus][S6], [polkit architecture][S7], [polkit application guide][S8].

## Adapter and ownership map

These are feasible source interfaces and example Bridge responsibilities. A capability is advertised only when the current adapter and session support it and policy permits discovery. Separate a capability supported by the environment from a grant issued to a specific client.

| Domain | Existing upstream interface | Bridge work and limits |
| --- | --- | --- |
| Session and displays | `org.freedesktop.login1` offers session, seat and lifecycle metadata. The compositor supplies actual display geometry, scaling and seat focus. | Map authenticated clients to allowed sessions. Publish output IDs, logical dimensions, scale and coordinate transformations where known. Suppress other sessions and reject stale output or session generations. Discovery does not grant lock/unlock, seat switching or control. [logind][S1], [Sway IPC][S4]. |
| Windows and focus | Sway tree, outputs and window events supply managed windows and focus. Compositor commands can request focus or close. AT-SPI also exposes accessible window and element focus. | Bind adapter-owned handles to the current epoch, keep compositor focus distinct from accessible focus, resolve app identity with provenance, report ambiguity. Only dispatch narrowly defined mutations and check state afterward. Close is a window request and can be refused, deferred or prompt for save. [Sway IPC][S4], [AT-SPI Accessible][S9]. |
| Semantic state and actions | AT-SPI D-Bus and libatspi expose registered application trees, optional interfaces and event listeners. | Correlate trees to windows where justified, normalize roles/states/actions with source and completeness, redact content, bound queries and issue opaque IDs. Check interface and handle validity before a scoped semantic mutation. [AT-SPI Accessible][S9], [AT-SPI EventListener][S10]. |
| Pixels and input | Compositor capture/virtual-input interfaces or portal ScreenCast/RemoteDesktop with PipeWire and EIS on supporting backends. A view-only wayvnc attachment is a candidate for the pinned Sway session. | Keep frame, live view and input grants distinct. Bind capture to the selected source, stop on revocation, and lease all agent input including semantic mutation. Surface capture scope honestly. Whole-output viewing can reveal any visible window, so use a dedicated session when filtering cannot enforce the requested scope. [ScreenCast][S11], [RemoteDesktop][S12], [wayvnc][S13]. |
| App catalogue | XDG Base Directory and Desktop Entry rules describe desktop IDs, lookup precedence, display metadata, `TryExec`, `Exec` and optional `DBusActivatable`. `dpkg-query` inventories installed packages, with no one-to-one mapping to desktop applications. | Distinguish installed package, discoverable desktop entry, policy-approved launch target and running window. Respect `Hidden`, visibility rules and availability. Treat user-writable entries as untrusted metadata. An agent launch allowlist should bind trusted entries or executables to validated arguments and ignore unauthorized overrides. [Desktop Entry 1.5][S14], [XDG bases][S2], [dpkg-query][S24]. |
| App lifecycle | A vetted desktop launcher may activate an existing D-Bus app or start a process. Compositor, process supervisor and accessibility bus supply different lifecycle signals. | Separate launch accepted, process started, window mapped, accessibility available, window closed and process exited. Multi-window, background and single-instance apps break one-to-one assumptions. Attribute events to a launch only when supported by the evidence. Provide window close separately from supervised app/process termination. [Desktop Entry 1.5][S14], [Sway IPC][S4], [systemd manager][S6]. |
| Processes and resources | `/proc` supplies PID, owner, status, process and resource counters subject to namespace, permissions and mount policy. cgroup v2 provides workload-level CPU/memory/I/O accounting and events. pidfds provide stable kernel references to processes after acquisition. | Expose only allowed processes and fields. Prefer a pidfd obtained during supervised launch. If discovery supplies a PID, verify the process lifetime and identity after opening the pidfd and before signaling. Never expose arbitrary command lines, environments or open files by default. Scope launch/terminate to approved jobs, use a fixed executable and typed arguments, and define subprocess ownership and termination policy. [procfs][S15], [cgroup v2][S16], [pidfd_open][S17], [pidfd_send_signal][S18]. |
| Services and diagnostics | systemd's per-user and system managers expose unit properties, lifecycle signals and jobs. System operations can require polkit. Kernel and service logs can contain secrets. | Map selected units to allowed health/status fields. Scope state changes separately, preferably to project-owned user units. Subscribe only to permitted sources. Treat job removal, command completion and resulting unit state as separate outcomes. Return bounded, sanitized diagnostics rather than raw journal access. [systemd manager][S6], [polkit][S7]. |
| System and devices | OS release metadata, kernel `/proc`, cgroups and filesystem statistics can report OS, CPU, memory and storage. Kernel netlink and device/udev metadata can describe permitted links/devices. | Define snapshot units, sample times and scope (machine, namespace or cgroup). Filter addresses, serial numbers, device names and mount paths. Distinguish reporting that a device exists from permission to use it. Defer camera, microphone, USB passthrough, network administration and package mutation. [os-release][S19], [procfs][S15], [cgroup v2][S16], [kernel networking specs][S20], [udev][S21]. |
| Files | OS permissions and mount namespaces bound filesystem access. `openat2` can constrain path resolution relative to a trusted directory FD on supported kernels. | Grant named roots and operations separately for listing, reading, creation, write/rename and deletion. Validate the operation against authorized roots, use FD-relative resolution and retain the resolved FD where possible. Decide symlink/mount policy and handle races on mutation, hardlinks, size quotas and conflict reporting. A prefix string check cannot enforce confinement. Defer file mutation until its semantics are proven. [openat2][S22], [systemd sandbox options][S23]. |

High confidence applies to the documented primitives above. Bridge normalization, app/window attribution, end-to-end denial, process ownership, namespace policy and runtime availability have medium confidence until measured in the chosen session. For processes, prefer launch supervision with a known lifecycle or existing approved user units. A general process killer based on caller-supplied PIDs would not meet this design. For files, a dedicated workspace and filesystem isolation provide another boundary in addition to path validation.

## Public command and event contract

The following is a proposal for the post-spike contract, not a list of stable endpoints. M1 needs only discovery, one snapshot and semantic action, denial and a small event channel, followed by the viewer/fallback experiment.

| Contract concern | Proposed behavior |
| --- | --- |
| Discovery | Return server/API version, compatible features, active session epoch, adapter health and grants. An operation descriptor includes versioned identifier, parameter/result types, validation limits, scope, authorization and consent requirements, cancellation class, replay behavior and bounded error categories. Only advertise discoverable resources. |
| Examples | `ListWindows` requires metadata read. `GetElementTree` may omit text and values without a content grant. `InvokeElement` requires a specific mutable target and current control lease. `CaptureFrame`, `StartStream`, `LaunchApp`, `TerminateJob` and `ReadWorkspaceFile` each have independent policy. A trusted human has a separate identity, with preempt/revoke rights controlled by OS policy. |
| Dispatch | Decode and bound requests, authenticate identity, resolve scope and target, authorize against live policy, validate revision, session and control lease, then dispatch through an adapter. Recheck after queue waits. Serialize competing input actions per session. If window or element freshness cannot be established, return a conflict or unavailable result. Keep server acceptance, dispatch, upstream acknowledgement and verified state separate. |
| Command lifecycle | Use a request/correlation ID and a server-owned job ID for asynchronous work. Record accepted, running, completed, denied, timed out, canceled or outcome unknown as appropriate. Cancellation prevents undispatched work or requests cooperative cancellation of running work. It cannot undo an already delivered input or external side effect. Disable automatic retries for unsafe mutations. Where a job can be queried after disconnect, require the original identity and current authorization. |
| Errors | Version the domain categories for denied, unsupported, unavailable, expired target, conflict, resource exhausted, deadline and outcome unknown. Map to transport status without conflating the meanings. Prevent guessed target IDs or cross-session references from acting as existence oracles. Diagnostics expose scope-safe metadata and adapter error classes. |
| Events | Use monotonically increasing sequence numbers within a documented stream/epoch and explicit ordering of Bridge-observed events, rather than claiming a total upstream order across D-Bus and Wayland. Take a revisioned snapshot and subscribe with a watermark, buffering bounded deltas if needed. Scope streams and cursors to the authorized identity and filter. Track drops/overflow explicitly, including broker/adapter gaps where observable. |
| Reconnect | Reauthenticate, reevaluate grants and control, and resume only if epoch, stream and cursor are valid and retained. Otherwise force a new snapshot. Replay only permitted events under current policy. Bound queues, depth, bytes and rate. If an event source cannot provide a consistent snapshot or a known cursor, expose the limit and invalidate state. Disconnect releases the lease and cancels queued input. |

### Window and element freshness

Do not make PID, an X11 identifier, compositor container ID, D-Bus object path or application-provided accessibility ID a permanent public identifier. Maintain a session epoch and per-source generations. Associate a candidate tree with a window only if the current lifecycle and evidence support it. A restarted app or reused object path must not redirect a previous reference. Treat missing optional interfaces, absent fields, redacted fields, timeout, defunct object and ambiguous mapping as distinct. Use focus/window events to invalidate snapshots. Before focus-sensitive input, compare both compositor focus and, where relevant, the accessible target. A focus check followed by synthetic input can race. If the selected backend cannot bind dispatch closely enough to the verified target and lease, the capability remains unavailable for that scope. [AT-SPI Accessible][S9], [AT-SPI EventListener][S10], [Sway IPC][S4], [interaction model](../INTERACTION_MODEL.md).

### Observer and human takeover

Keep the view-only media connection and Bridge control session separately authenticated. Bind a media authorization to an approved source, identity and lifetime, and close the underlying producer when the last viewer leaves. A raw RFB or compositor endpoint outside that policy can defeat separation. For the M1 view-only candidate, disable viewer input, verify clipboard isolation and keep the endpoint private. Run human takeover through a separately trusted local path on the same session. Control preemption needs a server-side epoch change, canceled queued input and release of pressed keys/buttons or closure of the synthetic seat, as supported. Do not transfer ownership while previously queued input can still be delivered to the new controller's focus. Report limits on in-flight actions. An interactive remote viewer would need an equivalent control-arbitration path before being enabled. [wayvnc][S13], [RemoteDesktop portal][S12], [ADR 0004](../DECISIONS/0004-desktop-and-human-observation.md).

## Protocol and transport

Keep the same command schema and domain error semantics across transports. Only the connection, authentication proof and runtime-discovered capabilities vary. Evaluate **gRPC with Protocol Buffers** first for a typed contract and bounded event stream. Keep JSON-RPC as a bounded fallback if the local channel integration or peer identity is too costly. Delay the wire-format decision until after a focused spike. Media has different frame size, privacy and backpressure requirements and can remain a separately authorized data path. [ADR 0002](../DECISIONS/0002-native-loopbridge.md), [gRPC concepts][P1], [Proto3 guide][P2].

| Option | Contract, lifecycle and performance | Maintenance and security considerations |
| --- | --- | --- |
| gRPC + Protocol Buffers | Generated schemas for .NET and Python, unary calls and server streaming, deadlines, cancellation signals and transport flow control. Define additive evolution, reserve removed field numbers/names and negotiate breaking API versions. Binary encoding can reduce payload size, but actual latency depends on adapter calls, scheduling and message sizes. | HTTP/2 stack and UDS integration add complexity, especially exposing the accepted socket's peer credentials to the policy layer. Verify both runtimes. Reconnect, cursor semantics, safe retry, identity and the authorization model remain Bridge responsibilities. [gRPC concepts][P1], [Proto3][P2], [cancellation][P3], [retry][P4], [.NET IPC guidance][P5], [Python gRPC][P6]. |
| JSON-RPC 2.0 | Language-neutral requests, responses, notifications and errors. Needs a specified schema, version negotiation, framing on a byte stream and explicit subscription/stream flow control, cancel, resume and resource limits. Readable payloads can help the spike. | Can be easier for a small local proof if paired with one defined UDS framing, but generates fewer guarantees without separate schema/client tooling. Parsing, tree size and JSON serialization costs require comparable measurement. The specification delegates transport and auth. [JSON-RPC 2.0][P7]. |
| WebSocket | Full-duplex message transport, useful when browser access is required. Pair with a defined message contract such as JSON-RPC. It supplies no typed command schema, durable subscription, replay cursor or action cancellation by itself. | Defer browser networking until there is an approved use case. Enforce authenticated encrypted connections, origin policy for browser clients, per-message bounds and current grants. An established socket does not confer control. [RFC 6455][P8]. |

| Deployment | Candidate transport | Trust boundary and evidence required |
| --- | --- | --- |
| Local agent | Filesystem Unix-domain socket in a private runtime directory. UDS where supported by the selected gRPC server/client combination. | Verify directory and socket ownership/mode, peer identity with `SO_PEERCRED` on the accepted connection, and an explicitly provisioned client identity with scoped, revocable grants. Peer UID alone does not distinguish same-user processes. Confirm that the selected stack preserves peer information through any proxy. Use a separate UID or OS sandbox for hostile clients. [unix(7)][P9], [XDG runtime directory][S2], [gRPC core naming][P10], [.NET IPC guidance][P5]. |
| External agent to a VM | Later authenticated proxy on a dedicated host-only network, or a narrowly scoped AF_VSOCK adapter when host, guest, kernel and hypervisor support it. | Keep an explicit bind and host firewall, prove reachable only through the intended interface and authenticate the end client or an explicitly trusted broker that securely conveys identity. Encrypt/authenticate the private network path. A host loopback port or vsock CID does not identify the agent. Prove behavior on reconnect, guest reboot and CID/address reuse. [vsock(7)][P11], [gRPC authentication][P12], [ADR 0005](../DECISIONS/0005-security-and-transport.md). |
| Remote agent | Explicit opt-in listener with mutually authenticated encrypted transport, for example mTLS with enrolled client credentials, and local revocation. | Remote mode starts disabled. Require a protected pairing path, separately scoped grants, credential rotation, reauthorization during long sessions and independent media consent. Test denied connections, revocation and listener exposure before enabling a non-local listener. [gRPC authentication][P12], [security model](../SECURITY_MODEL.md). |

On supported Linux, Python and .NET offer viable gRPC stacks and official documentation. The docs establish gRPC streaming and Unix-socket support in the cited libraries, with **medium** confidence for the full peer-identity path in the eventually chosen server. Select language based on accessible adapter bindings, process integration and proof size rather than forcing the Bridge and all clients to use one language. No remote forwarding, direct AF_VSOCK RPC, production pairing or media wire protocol is required to decide whether AT-SPI is usable in M1. [gRPC Python][P6], [.NET IPC][P5], [gRPC naming][P10].

## Fail-closed security model

The control plane admits an authenticated identity only into its granted scopes. Connecting, being in the same VM or running under an OS account carries no administrative grant. Default deny applies before discovery of sensitive targets, at dispatch and at delivery of event/media data. Denied grants, stale target, failed adapter, consent failure or unexpected disconnect must stop or reject that path. A fallback such as pixels, pointer input or process termination is a distinct authorized action. No `uinput`, raw device access, arbitrary shell or privileged escape hatch is part of the Bridge interface. [Security model](../SECURITY_MODEL.md), [ADR 0005](../DECISIONS/0005-security-and-transport.md).

| Risk | Initial constraint and verification |
| --- | --- |
| Cross-user/session access or same-UID ambient access | Bind identity, session, target and lease at every boundary. Isolate the agent process from desktop sockets, bus and credentials. Test an authorized account with an unenrolled process, a separate UID and an attempted cross-session reference. Check denied discovery leaks no target details. |
| Sensitive accessible content and pixels | Treat document text, element labels, window titles, password-related metadata, notifications and frames as sensitive. Filter snapshots, events and diagnostics consistently. Avoid broad output capture in a mixed-sensitivity desktop. If the backend cannot guarantee scoped capture/redaction, deny it or limit capture to a dedicated fixture session. Do not relay clipboard by default. |
| Credentials, devices and external side effects | Keep credentials out of agent-visible environment, `/proc` data, logs and fixture sessions. Do not forward host credentials or mount host home. Device/clipboard/network permission is independent. Protected prompts and sensitive workflows need trusted human or higher-level policy; low-level UI input can still initiate external effects. Start with no authenticated real services or sensitive data. |
| Prompt injection in applications | Treat web text, document content, accessible labels and screenshots as untrusted data with provenance. They cannot add grants or bypass confirmation. Restrict execution scope and outbound network at OS policy boundaries. Check sensitive commands at the Bridge boundary where they can be identified; generic clicks cannot reliably infer business intent. |
| Revocation, contention and dropped connections | Human can revoke without agent cooperation. Bind control to a time-limited lease and invalidate it on switch, expiry or disconnect. Stop streams, invalidate cursors and cancel queued mutations. Test takeover with a held key and in-flight action, a slow subscriber and app/Bridge restart. |
| Host/guest and supply chain | Disable or explicitly scope shared folders, clipboard, host networking, USB and credential forwarding. A VM snapshot does not undo external side effects. Verify image and dependency provenance, sign releases, plan rollback and audit package/update scope separately from Bridge permissions. [Foundation release path](M0_5_LINUX_FOUNDATION.md#sustainable-release-path). |
| Audit | Log time, identity, session, grant decision, operation class, correlation ID, adapter outcome and sanitized error. Protect log access, bound retention and separate diagnostic data from audit records. Omit raw frames, full trees, arbitrary arguments, credentials and document text. Check audit records for negative cases and accidental secret retention. |
